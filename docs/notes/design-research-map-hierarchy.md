# Design research (c) — map-app hierarchy and colour under bright sun

**Bounded question:** what do shipping map apps do about hierarchy and colour, and what holds up outdoors in daylight?

**Answer.** The restrained line (Google/Mapbox/Apple) converges on the same three moves: a drastically small map palette so few colours own meaning, a muted/desaturated basemap beneath data-dense overlays, and chrome contrast created by strokes/shadows instead of colour. The playful line (Waze/Tzel) buys back colour through disciplined vectors: one geometric world, flat colour, and round type — personality at the chrome level, never on the data layer. In bright sun, nothing ship-worthy relies on subtle saturation differences; they rely on luminance contrast, redundant encoding, and yellows/suns kept away from any value that must stay readable.

**Verified (primary/shipped sources; dates as on page):**

- Google Maps "Exploring Color": reduced a ~700-colour palette to 25 major/minor tones, removed subtle tones and transparency effects, tracked top colour pairings per zoom level as an accessibility matrix, and found the simplification unlocked *more* natural detail — https://design.google/library/exploring-color-google-maps/ (undated on page; described by the Maps team; accessed 2026-09-20).
- Mapbox Standard core style: "symbolic realism" chosen because customers want "a map style that is optimized for clarity, legibility, and flexibility to use as a canvas to display location data"; four lighting presets (Day/Night/Dusk/Dawn) move shadows with sun position — https://www.mapbox.com/blog/standard-core-style (published 2023-08-08; accessed 2026-09-20).
- Apple HIG Maps: two emphasis styles — default (saturated) vs **muted** (desaturated) "great if you have a lot of information-rich content that you want to stand out"; custom controls need "enough contrast between ... controls and the map. Consider a thin stroke or light drop shadow"; overlays sit above roads / above labels; zoom gates detail ("adjust map detail based on the zoom level") — https://developer.apple.com/design/human-interface-guidelines/maps (changelog through 2024-12-18; accessed 2026-09-20).
- Undercover (Singapore gov shade-routing, Umbra's closest kin): three routes presented as one decision — shortest / most shaded / recommended — with shade-coverage percentages as headlines; validated behavior, not just prose ("save time or sweat less"). Early trials: 95% of users chose the recommended path — https://www.hack.gov.sg/2026/undercover/ (published 2026-02-03; accessed 2026-09-20).
- RainViewer 8.0: a design update became a product update — "Glass ... only looks right when there is little of it"; the map screen kept radar + one player + one text layer button ("the name of the active layer is written on the map"); one time on the player; an "honest timeline" whose markers adapt to range so real coverage gaps stay visible as gaps — https://www.rainviewer.com/uk/blog/radar-wins-the-map-screen.html (published 2026-09-09; accessed 2026-09-20).
- Pentagram/Waze: the playful pole is systematic, not arbitrary — a city-grid "Block by Block" visual language, flat colour on a minimalist interface, round-cornered Boing logotype, and redrawn illustration "to pare away unnecessary elements and make them look like they belong to the same system" — https://www.pentagram.com/work/waze (undated on page; accessed 2026-09-20).
- Tzel: brand-forward shade routing with the same decision-pair Umbra sells — "fastest vs shadiest, side by side", a draggable sun, and a big "42% shade" chip next to feels-like — https://www.tzel.app/ (accessed 2026-09-20).
- ShadeMap: time-manipulated shadow visualisation with accumulation layers — the direct visualisation predecessor — https://shademap.app/ (accessed 2026-09-20).
- ColorBrewer documents palette paths rated for colour-blind safety and print/photocopy survival — https://colorbrewer2.org/ (accessed 2026-09-20).

**Inferred (synthesis).** Outdoors-in-sun rules Umbra should treat as axiomatic: luminance contrast before hue contrast; no critical text below WCAG AA 4.5:1 on the lightest realistic card surface; shadow data blue-dominant (repo invariant #5) means the route/data hue budget is already spoken for — chrome colours must not fight the blue; sun-dials/heat accents may heat up but no state should be *encoded* only by warmth, because glare and colour-blindness kill hue under sun.

**What this changes for Umbra.** Hierarchy budget for the candidates: muted basemap beneath overlays (U2), the Undercover/Tzel three-way verdict as the route-card spine (U3), RainViewer's one-time honest timeline (U4), and no amber/blue clashes against the shadow layer.
