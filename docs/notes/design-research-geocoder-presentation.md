# Design research (e) — geocoder result presentation

**Bounded question:** what do modern geocoder products return and present, and which constraints bind Umbra's search (P3/U6)?

**Answer.** The category leaders all separate *suggest* from *retrieve*: typing returns lightweight, styled suggestion rows (icon, name, secondary address line, distance) with a session token; selection fetches detail. Umbra's constraint is settled and verified — Nominatim forbids client-side autocomplete outright — which makes Foursquare (typeahead + rich row) the only compliant path, with Foursquare already returning every field a rich row needs.

**Verified (primary sources, accessed 2026-09-20):**

- OSMF Nominatim usage policy, "Unacceptable use": "Auto-complete search — This is not yet supported by Nominatim and you must not implement such a service on the client side using the API" (plus 1 req/s max, attribution, proxy/caching). Verified as the basis for Umbra's no-autocomplete invariant — https://operations.osmfoundation.org/policies/nominatim/.
- Foursquare Places API, Autocomplete: query ≥3 chars; `ll` + `radius` (default 5000 m, *biases* rather than restricts); `types` = place/search/geo; `bias`; `session_token` groups query+selection "for billing purposes. If the session_token parameter is omitted, the session is charged per keystroke/request"; `limit` 1–50, default 10; results carry `type`, `text`, `icon`, `link` plus place/search/geo objects — https://docs.foursquare.com/fsq-developers-places/reference/autocomplete (docs "updated 2 months ago" ≈ 2026-07).
- Foursquare Places response fields (what a rich row can already show): `name`, `categories[].{id,name,icon{prefix,suffix}}` at 32–512 px, `location` breakdown (address/locality/region/postcode/country), `distance` meters, `hours` with a formatted `display` string + `open_now`, `rating` 0.0–10.0, `photos`, `price`, `tel`, `website`, and a `veracity_rating` 1–5 for data confidence (honesty-guardrail gold) — https://docs.foursquare.com/fsq-developers-places/reference/response-fields.
- Google Places Autocomplete (New): returns place predictions plus optional query predictions "designed to be presented to the user to aid them in selecting the intended place"; Place Details (New) enriches the selection; results filtered by `includedPrimaryTypes` — https://developers.google.com/maps/documentation/places/web-service/place-autocomplete.
- Mapbox Search Box `/suggest` → `/retrieve` pattern: suggestion objects include `name`, address (formatted + `full_address`), `feature_type`, a `maki` icon assignment, `poi_category`/`poi_category_ids`, `brand`, and `distance`/`eta` metadata; "It does not include geographic coordinates" until `/retrieve` — https://docs.mapbox.com/api/search/search-box/.
- Apple HIG Maps: search field "combined with a way to filter locations by category"; for compact presentation, "a map pin icon with a place name" — https://developer.apple.com/design/human-interface-guidelines/maps.

**Inferred (synthesis).** The consensus row anatomy is: leading category icon/photo → name (match text normal weight) → one secondary address line → trailing distance (and hours·"open now" when available), with 44px-tall targets, keyboard-first interaction, and distanced-based ordering inside the chosen radius. Nothing in the leaders encodes *importance* above *distance* in mobile local search — which is the opposite of Umbra's current Nominatim ranking-by-importance comment in `search_places`.

**What this changes for Umbra.** U6: Foursquare-autocomplete rich rows (category icon via FSQ icon URL, address, distance, hours/open, maybe photo) exactly as the API's fields allow, session-token to avoid per-keystroke charges, and distance-first ordering for the assistant's `search_places` plus its pin presentation. The OSMF policy test must keep passing (submit-triggered Nominatim only).
